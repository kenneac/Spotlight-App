# Spotlight — Convex Backend

Backend documentation for the Spotlight app. For the mobile client, see [`README.md`](./README.md).

## Summary

This is the Convex backend that powers **Spotlight**, a photo-sharing social app. It defines the database schema (users, posts, likes, comments, follows, bookmarks, notifications), exposes authenticated queries and mutations that the mobile client subscribes to, stores uploaded post images in Convex file storage, validates Clerk-issued JWTs on protected calls, and keeps the `users` table in sync with Clerk through a Svix-verified webhook.

`Convex, TypeScript, Clerk, Svix, npm`

## Functions / Features

- 🔐 **Authentication on protected functions** — every user-scoped function resolves the caller from `ctx.auth.getUserIdentity()` (Clerk JWT subject matched against `users.clerkId`)
- 👤 **Automatic user provisioning** — the Clerk `user.created` event creates the matching `users` row (idempotent: skipped when `clerkId` already exists)
- ✏️ **Profile read and update** — fetch a user by Clerk id or document id; edit `fullname` and `bio`
- 📸 **Post creation with direct file upload** — the client requests an upload URL, uploads the image straight to Convex storage, then creates the post with the returned `storageId`
- 🧾 **Chronological feed** — all posts newest-first, enriched with author info and the viewer's `isLiked` / `isBookmarked` flags
- ❤️ **Like / unlike toggle** — maintains the `likes` table plus the denormalized `posts.likes` counter and notifies the author (unless it is their own post)
- 💬 **Comments** — add a comment, increment `posts.comments`, notify the author; list comments with author name and avatar
- 🔖 **Bookmarks** — toggle per user and post, and list a user's bookmarked posts
- ➕ **Follow / unfollow toggle** — maintains the `follows` table plus the `followers` / `following` counters and notifies the followed user
- 🔔 **Notifications** — list `like` / `comment` / `follow` events with sender info, the related post and comment text
- 🗑️ **Post deletion with cascade cleanup** — removes the post's likes, comments, bookmarks and notifications, deletes the stored file, and decrements the author's post count
- 📊 **Denormalized counters** — `users.posts`, `users.followers`, `users.following`, `posts.likes`, `posts.comments`
- 🌐 **HTTP webhook endpoint** — Svix signature-verified Clerk webhook at `POST /clerk-convex-webhook`

## Data Model (`convex/schema.ts`)

All tables are defined with `defineTable` and `convex/values` validators. Every document additionally has Convex's built-in `_id` and `_creationTime` fields.

| Table | Fields | Indexes |
| --- | --- | --- |
| `users` | `username`, `fullname`, `email`, `bio?`, `image`, `followers`, `following`, `posts`, `clerkId` | `by_clerk_id` (`clerkId`) |
| `posts` | `userId → users`, `imageUrl`, `storageId → _storage`, `caption?`, `likes`, `comments` | `by_user` (`userId`) |
| `likes` | `userId → users`, `postId → posts` | `by_post` (`postId`), `by_user_and_post` (`userId`, `postId`) |
| `comments` | `userId → users`, `postId → posts`, `content` | `by_post` (`postId`) |
| `follows` | `followerId → users`, `followingId → users` | `by_follower` (`followerId`), `by_following` (`followingId`), `by_both` (`followerId`, `followingId`) |
| `notifications` | `receiverId → users`, `senderId → users`, `type` (`"like" \| "comment" \| "follow"`), `postId? → posts`, `commentId? → comments` | `by_receiver` (`receiverId`), `by_post` (`postId`) |
| `bookmarks` | `userId → users`, `postId → posts` | `by_user` (`userId`), `by_post` (`postId`), `by_user_and_post` (`userId`, `postId`) |

- `posts.storageId` references the built-in `_storage` table used by Convex file storage (kept so a post's file can be deleted together with the post).
- Counter fields are denormalized: `users.posts` / `users.followers` / `users.following` and `posts.likes` / `posts.comments` are manually incremented and decremented by mutations.

## Functions Reference

Legend: **Q** = public query, **M** = public mutation, **IM** = internal mutation. "Auth required" means the function calls `getAuthenticatedUser` (or `ctx.auth.getUserIdentity()`) and throws `"Unauthorized"` / `"User not found"` otherwise.

### `convex/users.ts`

| Function | Type | Args | Auth | Behavior |
| --- | --- | --- | --- | --- |
| `createUser` | IM | `username`, `fullname`, `image`, `bio?`, `email`, `clerkId` | internal only | Looks up `by_clerk_id`; returns early if the user already exists. Otherwise inserts a `users` row with `followers`, `following`, `posts` initialized to `0`. Called by the webhook (see below). |
| `getUserByClerkId` | Q | `clerkId` | public read | Returns the user document matching `clerkId` via `by_clerk_id` (`.unique()`), or `null`. |
| `updateProfile` | M | `fullname`, `bio?` | required | Patches the authenticated caller's `fullname` and `bio`. |
| `getUserProfile` | Q | `id` (`users`) | public read | Returns the user document, throws `"User not found"` when missing. |
| `isFollowing` | Q | `followingId` (`users`) | required | Returns `true` when a `follows` row exists for (caller, `followingId`). |
| `toggleFollow` | M | `followingId` (`users`) | required | If a follow exists it is deleted and counters decremented; otherwise a follow row is inserted, counters incremented, and a `"follow"` notification is created for the followed user. |
| `getAuthenticatedUser` | helper | — | — | Plain async helper (not a Convex function) shared by all modules: reads `ctx.auth.getUserIdentity()`, resolves `identity.subject` through `by_clerk_id`, and throws when not authenticated or the user row is missing. |

Counters are updated by the module-private `updateFollowCounts` helper (`+1`/`-1` on `following`/`followers`).

### `convex/posts.ts`

| Function | Type | Args | Auth | Behavior |
| --- | --- | --- | --- | --- |
| `generateUploadUrl` | M | — | required | Returns a Convex storage upload URL (`ctx.storage.generateUploadUrl()`). The client uploads the image file directly to this URL. |
| `createPost` | M | `caption?`, `storageId` (`_storage`) | required | Resolves the public URL with `ctx.storage.getUrl` (throws `"Image not found"` if invalid), inserts the `posts` row starting at `likes: 0`, `comments: 0`, increments the author's `posts` counter, returns the new post id. |
| `getFeedPosts` | Q | — | required | Loads all posts newest-first (`.order("desc")`), and for each attaches `author` (`_id`, `username`, `image`) plus `isLiked` / `isBookmarked` for the current viewer. Returns `[]` when there are no posts. |
| `toggleLike` | M | `postId` | required | Removes the caller's like and decrements `posts.likes`, or inserts a like, increments the counter, and creates a `"like"` notification when the post is not the caller's. Returns `false` (unliked) or `true` (liked). |
| `deletePost` | M | `postId` | required + ownership | Throws unless the caller owns the post. Deletes related `likes`, `comments`, `bookmarks` and `notifications` (via their `by_post` indexes), deletes the file from storage, deletes the post, and decrements the author's `posts` counter (floored at 0). |
| `getPostsByUser` | Q | `userId?` | required when `userId` is omitted | Uses the given user id or the authenticated caller, then returns that user's posts through the `by_user` index. |

### `convex/comments.ts`

| Function | Type | Args | Auth | Behavior |
| --- | --- | --- | --- | --- |
| `addComment` | M | `content`, `postId` | required | Throws `ConvexError("Post not found")` when the post is missing. Inserts the comment, increments `posts.comments`, and creates a `"comment"` notification (with `commentId`) when the post is not the caller's. Returns the new comment id. |
| `getComments` | Q | `postId` | public read | Returns the post's comments via the `by_post` index, each enriched with `user: { fullname, image }`. |

### `convex/bookmarks.ts`

| Function | Type | Args | Auth | Behavior |
| --- | --- | --- | --- | --- |
| `toggleBookmark` | M | `postId` | required | Deletes the caller's bookmark and returns `false`, or inserts one and returns `true`. |
| `getBookmarkedPosts` | Q | — | required | Returns the caller's bookmarks newest-first and maps each to its post document (via `bookmarks.by_user` + `ctx.db.get`). |

### `convex/notifications.ts`

| Function | Type | Args | Auth | Behavior |
| --- | --- | --- | --- | --- |
| `getNotifications` | Q | — | required | Returns the caller's notifications newest-first (`by_receiver`), each enriched with `sender` (`_id`, `username`, `image`), the related `post` document (when present) and the comment `content` (for `"comment"` notifications). |

### `convex/http.ts` — HTTP route / webhook

| Route | Method | Purpose |
| --- | --- | --- |
| `/clerk-convex-webhook` | `POST` | Receives Clerk webhook events, verifies them with Svix, and provisions new users. |

Request handling (`httpAction`), in order:

1. Reads `CLERK_WEBHOOK_SECRET`; returns `500` if it is not set on the deployment.
2. Requires the `svix-id`, `svix-timestamp` and `svix-signature` headers; returns `400` when any is missing.
3. Reads the raw body and verifies the signature with `new Webhook(secret).verify(...)`; returns `400` on verification failure.
4. Parses the JSON body and validates it is an object; returns `400` on invalid payloads.
5. On `event.type === "user.created"`, extracts `id`, first email, `first_name`, `last_name` and `image_url` and calls `internal.users.createUser` with:
   - `email` = first email address, `clerkId` = Clerk user id
   - `fullname` = `"first last"` trimmed, `image` = `image_url ?? ""`
   - `username` = the part of the email before `@`
   - Returns `400` if id/email are missing and `500` if the insert throws.
6. Returns `200 "Webhook processed successfully"`. Other event types are acknowledged with `200` without writing to the database (only `user.created` is handled).

## Authentication

- `convex/auth.config.ts` registers a single auth provider:

  ```ts
  providers: [{ domain: process.env.CLERK_FRONTEND_API_URL!, applicationID: "convex" }]
  ```

  Convex uses this configuration (deployment environment variable `CLERK_FRONTEND_API_URL`) to validate Clerk-issued JWTs on every function call that requests an identity.
- Backend code does not call Clerk APIs directly; it consumes the validated identity through `ctx.auth.getUserIdentity()` and maps `identity.subject` to the `users.clerkId` field.
- `getAuthenticatedUser` (in `users.ts`) is the single choke point used by `updateProfile`, `isFollowing`, `toggleFollow`, `generateUploadUrl`, `createPost`, `getFeedPosts`, `toggleLike`, `deletePost`, `getPostsByUser` (when no `userId` is passed), `addComment`, `toggleBookmark`, `getBookmarkedPosts` and `getNotifications`.
- `getUserByClerkId`, `getUserProfile` and `getComments` are public reads and do not require an identity.

## File Storage

- `posts.generateUploadUrl` (mutation) returns a short-lived Convex storage upload URL; uploading is done directly by the client (the mobile app uses `expo/fetch` — see `README.md`).
- `posts.createPost` accepts the resulting `storageId` (`v.id("_storage")`), resolves a public URL via `ctx.storage.getUrl`, and persists both `storageId` and `imageUrl` on the post.
- `posts.deletePost` removes the file from storage with `ctx.storage.delete(post.storageId)` as part of its cascade cleanup.
- No other storage APIs (e.g. `getMetadata`, listing, transforms) are used.

## Scheduled Jobs

None. There is no `convex/crons.ts`, and no use of `ctx.scheduler` or Convex scheduled functions anywhere in `convex/`. All notifications and counters are updated synchronously inside the mutations that trigger them.

## Environment Variables

| Variable | Used by | Notes |
| --- | --- | --- |
| `CLERK_FRONTEND_API_URL` | `convex/auth.config.ts` | Clerk frontend API domain (issuer) that Convex validates Clerk JWTs against. Must be available to the Convex deployment when the auth config is pushed; locally it is present in the gitignored `.env` file. |
| `CLERK_WEBHOOK_SECRET` | `convex/http.ts` | Svix signing secret used to verify Clerk webhook signatures. Must be set as a Convex deployment environment variable; the webhook route returns `500` when it is missing. Not present in the repo's committed/ignored env files. |
| `CONVEX_DEPLOYMENT` | Convex CLI | Present in the gitignored `.env.local` ("Deployment used by `npx convex dev`"); names the dev deployment used for local development. Not read by backend function code. |

Client-side variables (`EXPO_PUBLIC_CONVEX_URL`, `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY`) are documented in the mobile README — they belong to the app, not to backend code.

## Caveats

- No test files or test runner exist for the backend; there is no CI configuration in the repository.
- No `convex.json` (project configuration) or deployment automation config is version-controlled.
- The webhook only acts on `user.created`; `user.updated` / `user.deleted` are not handled, so profile changes made in Clerk are not mirrored into `users` (updates happen through `users.updateProfile` from the app).
